## Abstract

The adapter pins Pi 1.3.0 while preserving native execution, session identity,
explicit extension selection and ACP-owned MCP configuration. Codemode is loaded
explicitly in parent and child processes because `--no-extensions` also disables
built-in extensions. Handled prompts complete without a model settlement event;
todo snapshots and bounded nested-call metadata survive native session reloads.
This prepares an adapter release; Lody still needs a separately built, checksummed
managed runtime before installed providers receive it.

## Decision

Use the existing RPC adapter and Pi's native codemode, without another executor,
version detector, polling window or background scheduler. External runtime overrides
must implement the same 1.3 contract. Keep built-in MCP disabled so the ACP-selected
server list remains authoritative.

Pi records nested tools as metadata on the outer result, without their full output.
Replay those ids, arguments and statuses without inventing missing results. The
packaged todo extension attaches its existing snapshot to codemode results and
restores from those results as well as direct todo results. No separate store is added.
Extension work detached from the submitted prompt remains unsupported.

MCP tools declare an output schema derived from the official SDK's text/image
result contract. Their existing model-facing content and error handling remain;
codemode additionally receives a JSON-validated structured result so `image()` can
forward image blocks. Built-in MCP discovery is not enabled.

## Evidence and validation

- Baseline 0.87.0: all unit tests, build and original native smoke passed.
- A synthetic wire test exposed the old indefinite wait for `handled`; the new
  disposition branch completes and admits the following prompt.
- The same real-CLI smoke runs ordinary and codemode-only tool selection. It
  covers MCP text/errors/images/rejected resources, question answers/cancellation,
  todo reload/resume, native session list/load, subagent lifecycle/output/cancel,
  Stop/recovery, stats/compaction, extension opt-in/exclusion/load failures and
  handled extension commands without model work.
- The codemode reload phase initially lost nested failures and todo state. Native
  `nestedCalls` replay and the outer result's todo snapshot address those failures.
- Effect checks exercise real file writes/reads/edits and shell execution, image
  input, cumulative usage, steering, provider-error recovery and child model selection
  and isolation. Valid synthetic PNGs replace a fixture Pi omitted as undecodable.
- A current-result image assertion exposed MCP images disappearing in codemode:
  without an output schema, scripts received only text. Structured MCP results now
  let `image()` deliver those image blocks to the model in both smoke modes.
- Local checks and both smoke modes also pass against a separately installed tarball
  on macOS with Node 24. The Check workflow verifies Linux and Windows x64/ARM64,
  including installed packages on Node 22 and Windows Node 24. Those results must
  be checked at the actual PR head; local tests do not establish Electron visual
  acceptance or real-provider quality.

## Scope

This change starts from adapter main and does not depend on slash-command PR #17.
It does not add that PR's command menu, change provider ids or convert session ids.
