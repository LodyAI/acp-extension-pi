# Pi 1.4 运行时

Status: implemented
Translation: current

[English](2026-10-28-pi-1.4-runtime.md)

PR: https://github.com/LodyAI/acp-extension-pi/pull/26

## 摘要

适配器将 Pi 固定升级到 1.4.0，沿用与 1.3.0 相同的 RPC 适配器、扩展显式选择和 ACP 管理的
MCP 配置。1.4.0 的改动集中在 Provider 模型目录、摘要输出上限和分类模型图片输入，
没有新增适配器使用的 RPC 命令、会话字段或扩展钩子。源码改动只有依赖版本、上报的 RPC
契约版本和本记录。已安装的 Lody Provider 仍需单独构建并校验托管运行时后才能获得更新。

## 决定

把 `@earendil-works/pi-coding-agent` 的精确版本从 1.3.0 提到 1.4.0，并同步
`PI_RPC_VERSION`（适配器作为 `agentInfo` 版本上报）。不增加版本探测、兼容分支或回退：
版本是精确固定的，外部 `LODY_PI_PATH` 运行时也必须实现相同的 1.4 契约。

1.4.0 保留了适配器驱动的全部 1.3 RPC 命令（`get_available_models`、
`get_available_thinking_levels`、`set_model`、`set_thinking_level`、prompt、steer、
abort、压缩和 stats），因此适配器的线协议和工具行为保持兼容。它不固定模型列表，
只上报所启动 Pi 版本暴露的内容。

同一 `~/.pi/agent` 配置下，1.4.0 比 1.3.0 多出一个可用模型
`opencode-go/minimax-m3.1-flash-free`，并从 OpenCode Go 移除了 `cat-jam-free`、
`space-bunny` 和 `step-5-preview-free`。1.4.0 还向内置 `minimax`/`minimax-cn` 目录
新增了 `MiniMax-M3.1-Flash`，只有配置了这些 Provider 的 profile 才会看到它。

`generateSummary()` 忽略 `reserveTokens` 以及 Provider 归属请求头属于 Pi 自己的模型请求
细节，不需要适配器配合。适配器不重新实现的原生行为确有变化：第三个 codemode 脚本现在
等待空闲 worker 而不是直接失败；恢复分支时会激活该分支记录之后才注册的扩展工具。
适配器契约不变，现有单元、线协议和 smoke 套件仍然通过，但这是兼容，不是原生行为完全一致。

## 证据与验证

- 在 macOS arm64 / Node 26.11.1 上 `pnpm check` 通过（类型检查、111 个测试含 1 个仅
  Windows 跳过、Prettier）。
- `pnpm build` 与 `pnpm smoke` 通过。smoke 通过确定性本地模型驱动官方 1.4.0 CLI，
  覆盖普通与仅 codemode 两种模式：MCP 文本/错误/图片、提问、todo、原生会话列出/加载、
  子代理、Stop/恢复和扩展显式选择。
- `pnpm pack` 加安装后 tarball smoke 通过，与 Check 工作流的打包步骤一致。
- 用现有 `~/.pi/agent` 配置调用 1.4.0 的 `ModelRuntime` 返回 35 个可用模型
  （OpenCode Go 33、Volcengine Agent Plan 2），同一配置下 Pi 1.3.0 返回 37 个。
  增删只有上面列出的四个 ID，差异属于模型目录，与 Lody 的能力缓存无关。
- 一个占满两个 worker 的合成 codemode 试验观察到：1.3.0 第三个脚本报
  `worker limit reached`，1.4.0 排队等待并在 worker 释放后执行。适配器从未实现该调度，
  因此不需要适配器改动。
- 适配器的 `supportedThinkingLevels` 与 Pi 1.4.0 内置的 1,599 个聊天模型全部一致，
  模型数据变动后它推导的思考档位仍然正确。
- `initializeResponse().agentInfo.version` 现在会与所安装 Pi 导出的 `VERSION` 比对。
  把 `PI_RPC_VERSION` 回退到 1.3.0 会让该断言失败；在此之前，同样的漂移整套测试仍然通过。

## 消融

- 回退 `package.json` 的 pin 而锁文件仍为 1.4.0，或删掉锁文件里的
  `pi-coding-agent@1.4.0` package 条目，`pnpm install --frozen-lockfile` 都会失败。
  这两处改动是关键路径。
- 回退 `src/version.ts` 这一处改动会通过此前全部检查，这正是上面那条线协议断言存在的原因；
  加上它之后，同样的回退会失败。
- README 与记录属于文档：没有检查依赖它们，保留只为准确性和决策记录。

## 局限

  仍绑定在 1.3 运行时的 PR 上。
- 托管运行时归档、校验和与 Lody 侧 manifest 由运维打包流水线生成并验证。本记录不声明
  公共制品已发布。
- Check 工作流的 Linux 与 Windows x64/ARM64 结果需以实际 PR head 为准；本地验证仅覆盖
  macOS。
